# وثيقة الدمج — المستودعات المفتوحة وإزاي اتحولت لمشروع شغال

> تاريخ المراجعة: نوفمبر 2026 — مراجعة عملية للمستودعات اللي اترشحت، وقرار الدمج النهائي لكل واحد.

## 1) المستودعات اللي اتراجعت

| المستودع | الفكرة | قرار الدمج |
|---|---|---|
| [OpenManus](https://github.com/FoundationAgents/OpenManus) | وكيل تنفيذ: خطة → أدوات → ملاحظة → تسليم | **اتدمج كمنطق أصلي بالTypeScript** داخل التطبيق — `src/lib/agent.ts` |
| [BullMQ](https://github.com/taskforcesh/bullmq) | طابور مهام دائم + عامل خلفية | **اتدمج الفكرة بدون Redis** — طابور على قاعدة البيانات (AgentRun بحالات queued/planning/running/done/failed) + تنظيف المهام المعلقة بعد إعادة تشغيل السيرفر |
| [LiteLLM](https://github.com/BerriAI/litellm) | بوابة موحدة لكل مزودين + احتياط عند الفشل | **اتدمج كراوتر أصلي بالTypeScript** — `src/lib/providers.ts`: 11 مزود (Gemini/OpenAI/Claude/OpenRouter/Groq/DeepSeek/Mistral/صينيين/مخصص) + سلسلة احتياط تلقائية |
| [Activepieces](https://github.com/activepieces/activepieces) | محرك أتمتة + موافقات بشرية | **اتدمجت الفكرة (Human-in-the-loop)** — كل مهمة وكيل بتتسجل في «بانتظارك» لموافقتك قبل الاعتماد |
| [OWL](https://github.com/camel-ai/OWL) / [OpenHands](https://github.com/OpenHands/openhands) | بدائل متعددة الوكلاء / برمجة | **ما اتضيفوش** — التداخل مع OpenManus يضيف تعقيد بدون قيمة حالياً |

## 2) ليه OpenManus اتحول لكود TypeScript أصلي؟

- OpenManus نفسه مشروع Python (يشغل `main.py` مع `config.toml`) — تشغيله كعملية جانبية مع تطبيق Next.js في ويب ساندبوكس واحد مش عملي (العملية بتموت مع إعادة تشغيل البيئة).
- عشان كده نفس الدورة بتاعته اتنفذت natively:
  - **Plan**: ندوة أول LLM call بترجع خطة 3-5 خطوات بأداة محددة لكل خطوة.
  - **Act**: تنفيذ فعلي بالأدوات — `web_search` (3 محركات بحث حقيقية)، `page_reader` (قراءة صفحات ويب)، `python` (تشغيل كود Python حقيقي بـ timeout)، `write_file` (ملفات تسليم حقيقية على القرص جاهزة للتحميل)، `image_gen` (توليد صور)، `finish` (تسليم).
  - **Observe**: نتيجة كل أداة بترجع للنموذج قبل الخطوة اللي بعدها.
  - **ضمان التسليم**: لو المهمة بتطلب ملف ولسه مفيش ملف — الوكيل بيتجبر يكتبه فعلاً قبل ما يسلّم.
- نفس الدورة ده تقدر تستبدلها بعملية OpenManus Python حقيقية لما تشغل المشروع على سيرفر خاص بيك — معمارية `startAgentRun` جاهزة للتوصيل بأي backend.

## 3) ربط Gemini — الاكتشافات العملية بتاعة مفتاحك

المفتاح اللي بعتّه بيبدأ بـ `AQ.` — ده مفتاح Google Cloud الجديد (مش AIza القديم)، والاختبار الفعلي طلّع النتائج دي:

1. `POST /v1beta/models/...:generateContent` بالموديل القديم `gemini-2.5-flash` → **اتلغى للمستخدمين الجداد** ورسالة جوجل بنفسها بتقول: استخدم **`gemini-3.8-flash`**.
2. `POST /v1beta/interactions` (الـ **Interactions API** — الواجهة الرسمية الجديدة GA من يونيو 2026) → **الـ endpoint ده اللي بيشتغل مع مفتاحك**: عدّى فحص المنطقة ووصل لـ rate limiter جوجل.
3. الحصة المجانية: **20 طلب/يوم** على gemini-3.8-flash — لما تخلص، التطبيق بينتقل تلقائياً للمحرك المجاني ويكمل، ولما الحصة ترجع يرجع لمفتاحك لوحده.
4. فحص المنطقة الجغرافية عند جوجل بيتطبق بالتناوب من سيرفراتهم — من السيرفر السحابي ده مفتاحك بيشتغل أحياناً وبينحجب أحياناً؛ **من جهازك في مصر هيشتغل بانتظام** بنفس الكود بالظبط.

الشكل النهائي للطلب (متخزن في `callGeminiInteractions`):

```json
POST https://generativelanguage.googleapis.com/v1beta/interactions
x-goog-api-key: <مفتاحك>
{
  "model": "gemini-3.8-flash",
  "system_instruction": "نظام الموظف...",
  "input": [
    {"type": "user_input", "content": [{"type": "text", "text": "..."}]},
    {"type": "model_output", "content": [{"type": "text", "text": "..."}]}
  ],
  "generation_config": {"max_output_tokens": 4096, "thinking_level": "low"},
  "store": false
}
```

## 4) توجيه ذكي للحصة (Smart Routing)

عشان الـ 20 طلب/يوم ميتستنزفوش على المهام الثقيلة:

- **الشات / الفريق / الاجتماعات / تحليل الصور** → مفتاحك الأول (طلب واحد لكل رسالة).
- **مهام الوكيل OpenManus** (خطة + خطوات + تسليم = 5-8 طلبات) → المحركات المجانية الأول، ومفتاحك كاحتياط لو المحركات المجانية وقعت.
- كل نجاح/فشل لمفتاحك بيتسجل تلقائياً في `ProviderKey.lastStatus` — الواجهة بتعرض الحقيقة دايماً في تبويب «المفاتيح» ووشارة «العقل» فوق.

## 5) إزاي تشغل المشروع عندك وتخلي مفتاحك هو العقل الوحيد

```bash
# على جهازك:
bun install
# حط مفتاحك في .env.local (نفس الشكل الموجود)
GEMINI_API_KEY=AQ.Ab8...
GEMINI_DEFAULT_MODEL=gemini-3.8-flash
bun run dev
```

أو من التطبيق نفسه: تبويب «المفاتيح» → ضيف مفتاحك → «اربط المفتاح» → الفحص الحقيقي هيشتغل ويظهر «المفتاح شغال والرد وصل فعلاً».
